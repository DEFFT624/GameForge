START HERE / NO CODING EXPERIENCE NEEDED

Your first few lines of code

Programming means writing precise instructions for a computer. C# (say “C sharp”) is the language we will use. These lessons start with text-based games so you can learn the logic before adding graphics.

1. Read an instruction

Console.WriteLine("Hello, adventurer!");

Console is the text window. WriteLine tells it to display a line. The dot selects that operation; parentheses hold what you pass to it. Quotes mark literal text, and the semicolon ends this instruction.

Its output is Hello, adventurer! — without the quotes.

2. Follow the order

Console.WriteLine("Open the door");
Console.WriteLine("Enter the room");

These instructions run from top to bottom. First the program prints Open the door, then Enter the room on the next line. Computers follow your instructions; they do not guess what you intended.

Predict: what if you swap these lines?

Enter the room prints first. Open the door prints second. The order of instructions changes the result.

3. Give a value a name

string playerName = "Nova";
Console.WriteLine(playerName);

string means text. playerName is a name you choose. = stores the value on the right. The second line reads that variable and prints Nova.

Other types include int for whole numbers and bool for true or false. You will meet them one at a time.

Symbols, mistakes, and how to use this course

C# cares about uppercase and lowercase: WriteLine and writeline are different. Use straight double quotes around text. Braces { } group instructions. Text after // on a line is a comment for humans. Spaces and indentation make code easier to read.

Read the goal, trace the example, then predict a small change before trying the quiz. The glossary explains unfamiliar words. Pass both the quiz and the code blank to complete a lesson; mistakes do not erase earlier progress.

A compiler checks and translates C# before it runs. A syntax error means the code breaks a language rule; a logic mistake means it runs but does the wrong thing. Start by checking the first error, spelling, quotes, and matching braces. You do not need to memorize everything.

Do I need to install anything?

No installation is needed to read, answer quizzes, or fill code blanks here. This website does not compile or run your C#.

When you are ready to run examples yourself, use a supported .NET SDK and a new C# console project. Put one lesson example at a time in Program.cs. These examples use top-level statements and implicit System imports; if imports are disabled, add using System; at the top. Classes and enums belong after the top-level instructions.

Microsoft’s C# getting-started tutorial ↗ explains the local setup. Installing tools is optional for this course.

When a program goes wrong

A compiler error prevents the new code from being built. A runtime error happens while a built program runs. A logic mistake lets it run, but it does the wrong thing.

  1. Save Program.cs and run dotnet run from the folder containing your project file.
  2. Start with the first error. Note its code, the file, and the line number. Later messages may come from the same first mistake.
  3. Compare expected and actual behavior. Change the smallest relevant part, save, and run again.
  4. Once it works, try a boundary case: zero health, an empty list, or an invalid choice. Keep a copy of your working version.

The examples below intentionally include mistakes. Try one at a time in a fresh console project when you are ready; this website displays them as text and does not run them.

If the terminal cannot find dotnet, check the SDK setup rather than changing your C# code. If you are stuck, share the first error and the small code block around it when asking for help.

      02 / YOUR FIRST PROJECT

      Dungeon of Three Rooms

      Turn the lessons into a tiny console RPG. Build at your own pace, and check each milestone when you have tested it yourself. This checklist saves in your browser.

      Before you build

      The quizzes and code blanks need no installation. Building the console game locally requires a supported .NET SDK and a C# editor. Use a new console project with top-level statements and implicit imports. Each lesson example is a separate Program.cs; do not paste all of them into one program.

      Start with fixed damage and a small inventory. Test invalid input, missing items, health limits, and every ending. GameForge does not install tools, run your project, or accept project files.

      Step 0: create and run your local project

      The lessons run as quizzes here. To build the RPG, you will write and run C# on your own computer. This website does not install software or run your code.

      1. Install a supported .NET SDK and choose a code editor. Follow Microsoft’s console-app setup guide if you need help.
      2. Open a terminal in a folder where you keep your projects. Choose a new folder name so you do not overwrite an existing project. Run these commands one at a time:
      dotnet new console -o GameForgeRpg
cd GameForgeRpg
dotnet run

      You should see Hello, World!. If the terminal cannot find dotnet, finish the SDK installation, reopen your terminal, and try again.

      Open Program.cs in that project. Replace the starter code with this small input check, save it, and run dotnet run again:

      Console.WriteLine("What is your hero's name?");
string? name = Console.ReadLine();
if (name == null)
{
    Console.WriteLine("Goodbye");
}
else
{
    Console.WriteLine(name);
}

      Use dotnet run in the terminal for programs that read input; an editor’s debug-output panel may not accept typing. Type Nova and press Enter. The program should print Nova. Console.ReadLine waits for a line of text. The ? in string? allows a missing value; null means input has ended. An empty line is still text.

      To test end-of-input in a typical terminal, use Ctrl+Z then Enter on Windows, or Ctrl+D on an empty line on macOS/Linux. You should see Goodbye. Terminal shortcuts can vary. Ctrl+C stops a running program; it does not test the null branch.

      Once that works, replace this input check with the hero from step 1. Add one feature at a time and save before running again. Keep a copy of a working version before making a large change.

      Compare with a complete C# reference

      Try the six build steps yourself first. Then use this first-party source to compare one feature at a time. This is a console game you run locally; nothing runs in your browser.

      Read the full C# source ↗ Save source as Program.cs ↓

      1. Complete Step 0 in a new project folder. Keep a copy of your own Program.cs before replacing it.
      2. Open the reference source, copy all of it into that project's Program.cs, and save. Replace the starter code completely; don't leave a second set of top-level instructions.
      3. Run dotnet run from that project folder. Type 1, 2, or 3, then press Enter. This example has no extra packages.

      Read it in four passes

      1. The starting values: hero, inventory, room, enemyHealth, and state describe what the game remembers. The two using lines make System and List available.
      2. The turn loop: Exploring creates one enemy. Combat reads one choice. A failed choice uses continue to begin the next loop check without an enemy turn.
      3. The action: the switch picks Attack, Potion, or Quit. A living enemy counters after a successful action. A defeated enemy never attacks.
      4. The ending: clearing rooms 1 and 2 moves to Exploring. Clearing room 3, losing all health, quitting, or ending input sets GameOver.

      || means “or”; ! reverses a true/false result. The input check rejects failed parsing or a number outside 1–3. string? allows the missing value null. Contains checks whether the list has a potion; Remove removes one matching item. Math.Min and Math.Max choose the smaller or larger number to keep health within its limit.

      Test before changing it

      Trace one fight before playing

      Use the normal reference settings: 100 hero health, a 25-health enemy, and two potions. Type each entry below and press Enter. Values are shown after that choice and any enemy counterattack. Predict the next row before reading it.

      The successful potion prints 100 before the enemy attack; the next menu shows 92. The defeated enemy prints zero health and does not attack. Clearing room 1 changes state to Exploring and advances the room number. The next loop creates a fresh 25-health enemy in room 2, while your 92 health and one remaining potion carry over.

      Type 3 to quit after this sequence. Compare the messages with the table, then explain why the failed choices did not cost health and why healing did not end the turn at 100. This walkthrough is optional and does not change your checklist or lesson progress.

      • Choose Attack nine times. You should clear exactly three rooms and win with 52 health.
      • Try abc, an empty line, 0, and 9. Each should ask again without changing health.
      • Try a potion at full health. It should remain in the inventory. After attacking, a potion heals up to 100 and consumes one item and one turn.
      • Choose Quit, or end terminal input. You should leave without another enemy attack.
      • The normal settings are forgiving. To test defeat, change only public int Health = 100; to public int Health = 10;. Two attacks should lead to defeat at zero health. Restore 100 afterward.

      When something differs from your project, compare the smallest relevant block. Explain the change in your own words before copying it. Checking a project milestone records your own testing; opening this reference does not complete lessons.
